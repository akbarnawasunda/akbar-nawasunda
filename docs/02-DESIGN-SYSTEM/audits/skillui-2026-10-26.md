## What is true in that, and what is not

| skillui said | measured truth (round 19) | verdict |
| --- | --- | --- |
| Fonts: 1, "do not mix font families" | Two families load: `displayFont` (Excess V Straight, hero H1 only) and `bodyFont` (Relidux, everything else). `npm run audit:fonts` enforces it. | **accidentally right** — the ransom-note cleanup landed; skillui cannot see *which* two, it only sees one generic name because both arrive as CSS variables |
| Primary theme: light | `--color-bg-base: #000000`, text `#ffffff`/`#b8b8b8`. The extractor keyed on the first background it parsed. | wrong |
| Heading weight 700 | Every weight declaration on the site is 400; both binaries are single-weight and `font-synthesis: none` forbids a fake bold. | wrong — it read the *fallback* chain's expectations, not the declarations |
| Body line-height 1.5 | `--leading-body: 1.6` on every paragraph (global `p` rule, round 19). | close, wrong |
| Motion: spring physics | No spring library exists. Motion is transform + the single rAF scroll engine (`src/lib/scroll-engine.ts`); `qa:motion` asserts 22 checks. | wrong — known skillui hallucination, also present in the 2026-10-24 run |
| 4px base grid, spacing 2…16 | Token scale `--space-1…32` (4px base) — but the site's air comes from `clamp()` section padding, not the small steps. | half right |

## Why this file exists

The owner's tool list ships Skill UI as the design-system extractor, and its output is the kind of
third-party read an owner trusts over the agent's own claims. It is kept here verbatim-plus-corrections
so the gap between "what the extractor sees" and "what the build serves" is documented, not argued.
The authoritative machines remain:

- `npm run audit:fonts` — the two-face contract, exit non-zero on violation;
- `npm run audit:tokens` — 86 tokens, no raw hex in CSS modules, no orphans;
- `docs/08-IMPLEMENTATION/design-review/round19/` — rendered proof, per route and viewport.

Skill UI is a scout, not a surveyor.
